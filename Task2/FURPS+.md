| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | На сайте клиент может подать заявку на депозит, оставив свой номер телефона и Ф. И. О. После этого ему позвонит менеджер кол-центра.                                |              |
| F2  | Показ доступных депозитов с актуальными ставками на сайте                                |              |
| F3  | В интернет-банке указав счет и сумму депозита, клиент может подать заявку на открытие депозита. Операцию необходимо будет подтвердить с помощью СМС-кода.                                |              |
| F4  | В MVP менеджер депозитного бэк-офиса обрабатывает заявку и подтверждает условия депозита в АБС. Клиент получает СМС после подтверждения ставки и еще одно СМС после открытия депозита.                               |              |
| F5  | В интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонализированные ставки лично для него.                               |              |
| F6  | 	Новый клиент проходит личную идентификацию с проверкой документов в отделении.                               |              |
| F7  | На сайте данные необходимо защищать с помощью механизма шифрования трафика.                               |              |
| F8  | В интернет-банке данные при передаче также надо защитить механизмом шифрования.                               |              |
| F9  | Менеджер просматривает заявку в системе кол-центра и может предложить особые условия.                              |              |
| F10  | 	Сотрудники депозитного и кредитного бэк-офисов должны иметь возможность работать со ставками по депозитам в рамках своих прав доступа.                              |              |
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс работы максимально удобным для клиента                                |              |
| U2  | Интерфейсы сайта и интернет-банка должны соответствовать дизайн-системе банка, включая цвета и брендированные элементы.                                |              |
| R   | Надежность (Reliability)           |              |
| R1  | 	Сервисы MVP, включая интернет-банк, должны работать круглосуточно с доступностью не менее 99,9%.                                |  Требуется уточнить период            |
| R2  | Возможнность аварийного переключения интернет-банка на резервный ЦОД в случае отказа основного                                 |  Уточнить допустимое время переключения            |
| P   | Производительность (Performance)   |              |
| P1  | Отклик по всем операциям должен занимать миллисекунды                                | Уточнить целевое время отклика по операциям. Ограничение описано в +R6            |
| P2  | Возможнность горизонтального масштабирования и распределения запросов между серверами, приложениями и ЦОД                                | Есть ограничения АБС, +R8             |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Поддержка интеграционного тестирвоания на тестовом контуре.                                | Дополниельное требование. Проверка совместной работы сервисов для избежания факапных релизов, отказов и откатов |
| S2    | Документирование решений                                |           |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Функционал работы с СМС реализован в ядре системы. Сейчас на стороне подрядчика, лучше реализовать собственными силами                                | Предпочтение - реализация собственными силами, доработка существующего СМС-функционала ядра требует участия подрядчика.             |
| +R2 | Рассмотреть размещение функций работы со ставками и согласования ставок по заявкам в АБС.                                | Вариант реализации. Сейчас ставки ведутся в XLS-файлах.             |
| +R3 |  Существующий стек баз данных банка MS SQL и Oracle. Новые технологии должны быть совместимы с действующими платформами. | Желательно учитывать экспертизу сотрудников банка |
| +R4 |  Лучше использовать Kafka на перспективу, текущая версия платформы интернет-банка несовместима с ней | Предпочтение. Текущая платформа интернет-банка несовместима с Kafka. |
| +R5 |  В рамках задачи открытия депозитов перевести интернет-банк на микросервис | Вариант к рассмотрению |
| +R6 |  При проведении платежей некоторые справочные данные загружаются больше секунды. | |
| +R7 |  Лучше избежать прямой работы интернет-банка с API АБС, т.к. база данных системы уже перегружена и онлайн-подача заявок на большое количество продуктов может поставить под угрозу работоспособность банка. | |
| +R8 |  АБС может масштабироваться только вертикально из-за своей базы данных | Ограничение текущей системы |
